# v0.2.16：补货预算保护与预检恢复

## 修复的问题

旧版池内切换先占用备用 IP，旧 IP 的补货任务稍后才检查额度。因此在本次总额度已经耗尽时，客户端连续更新 session 仍能耗尽备用池。旧版无预留的补货路径也缺少供应商余额校验；预算恢复判断只检查分组，账号预算不变时会反复进入队列。

现在所有会退役已使用 IP 的池内切换，先在调度锁内预留一次补货额度，再提交绑定变化。额度不足时，原 IP、原 session 和备用池保持不变，新 session 返回具体预算错误。第一次获配和未使用预留的转移不收费；释放绑定仍不调用 Webshare。原位、手动与定时换号继续使用同一套预算预留。

预留会占用可用预算，提交真实 Replace 时转为已提交，不重复扣一次。平滑切换的预留随旧连接排空保留，重启后仍有效；未提交的失败任务释放预留。账号本地累计安全预算、有效供应商余额（含未结算提交）、全局每日、分组每日、本次授权累计、席位连续次数和冷却均检查；最终 POST 前再检查一次。供应商余额缺失或过期时暂停提交，需同步套餐。

预算等待任务只在上述条件均允许时重新排队，不会仅因分组还有余额就重复唤醒。暂停期间不新增 Webshare 提交。已实际提交且结果不明的任务仍保留 UNCERTAIN，不通过自动重试猜测结果。

## 页面与额度说明

- 资源池显示“预算暂停”、具体限制来源与已用／上限／预留，提供分组额度入口；历史资源不再展示成当前工位的绑定。
- “本轮”明确改为“本次授权总上限（跨日累计）”，涵盖新 session、排空补货、质量筛查等所有实际分组换号；跨日、重启和普通保存不清零。
- “新筛选轮次”改名为“重新授权总额度”，确认框说明会从 0 重新授权多少次。仅追加少量次数时应编辑总上限，不必重置授权。其他预算限制继续有效。

## 预检超时

指定国家、ASN、号段等规则的 dry_run 预检最多执行 3 个检查窗口，每窗口最多 15 秒、10 次状态轮询。首次失败后等待 5 秒，第二次失败后等待 15 秒；仅超时、临时服务故障或未完成预检允许有限恢复。记录并持久化预检任务 ID，后续优先轮询原任务。没有取得 ID 的临时失败最多重发 dry_run，不重放真实 Replace。

超时不等于缺货，不触发随机兜底。只有供应商明确确认缺货才按既有配置兜底；验证成功后仍须通过最终预算检查才提交真实更换。达到上限后停止并保留旧资源，供人工核对。升级前已 FAILED 的旧任务不会自动重开。

## 升级与验证

延续 Docker Compose 部署，不修改任何既有额度、授权轮次或正常绑定，不自动提交换号测试。允许在仅有未提交的预算暂停任务、且无活动 TCP／等待请求／实际供应商在途任务的窗口更新。更新前成套备份 `.env`、`config/`、状态库与观测库。

状态快照增加预检 ID／次数，schema 升为 6。回退旧镜像必须同时恢复升级前数据库和配置；有新供应商提交时应先对账，不能盲目恢复旧快照。

回归覆盖：最后一次额度并发预留、预算耗尽保留绑定和库存、所有补货路径的供应商余额与过期保护、预检后余额变化、预算恢复完整条件、平滑排空预留持久化、预检 ID 持久化与有限重试、重启后不超过三次、预算状态与历史工位展示。供应商测试均使用模拟服务。
