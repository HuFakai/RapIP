# RapIP v0.2.5 升级方案

状态：已由用户批准执行，2026-11-05。本文保留设计目标，实际实现与迁移说明见 [v0.2.5 发布说明](RELEASE_V0.2.5.md)，验收与部署结果见 [验收记录](VALIDATION.md)。

本方案依据用户最新要求，替代原方案中“空闲 300 秒回收绑定、禁用 session、退役 IP”的设计。实现时须同步修订 SPEC.md 的绑定、空闲回收、故障转移、重启恢复、容量与配置章节，避免文档互相冲突。

## 1. 两种使用模式

| 模式 | 客户端配置 | 正常情况下何时换 IP |
| --- | --- | --- |
| 固定绑定（默认） | 同一组、同一工位、同一 session 长期使用 | 客户端更改 session 后缀，或管理员明确执行更换操作 |
| 定时轮换（按质量组开启） | 保持 session 和完整连接配置不变 | 在组内设定的间隔、活动条件和预算允许时轮换 |

质量组默认使用固定绑定，定时轮换默认关闭，不因升级自动启用。定时轮换与“质量不合格自动更换”是不同开关，页面与审计均区分来源。

## 2. 固定绑定与 session 生命周期

### 2.1 长期保留

- 同一组/工位/session 的绑定不因无连接、无流量或经过时间而失效。
- 所有 TCP 连接关闭后，仍持久保留绑定和该 IP 的独占归属；IP 不退回待分配池、不转交其他工位、不触发供应商更换。
- 再次使用同一配置时，继续使用原 IP；无须发送保活请求。
- session 是逻辑出口绑定标识，不是网站 Cookie 或登录会话。TCP 连接可反复建立和关闭。
- 同一工位换到从未使用过的新 session 时，先取得本组符合条件的待分配 IP，再原子提交切换。缺货或受限时保留旧绑定，明确报错。
- 成功切换后旧 session 被标为“已被替代”，迟到请求不能把工位切回旧 session。保留防重放记录与长期保留当前 session 是两件事。
- 同一绑定不允许通过修改 country 暗中改变路由；更改国家条件须更换 session 或执行明确的管理操作。不同组/工位允许使用相同 session 字符串。
- 无 worker 的匿名 session 继续作为独立绑定；改变匿名 session 会创建另一份绑定，原匿名绑定需明确释放，不因猜测“后缀变化”自动关联并退役。连接配置默认引导使用稳定 worker，方便主动换 session。

### 2.2 固定 IP 的严格程度

用户最新要求以“配置不变，IP 不变”为默认承诺。因此固定绑定模式默认不允许后台故障转移、质量复检或策略更新悄悄更换已绑定的 IP。

- 临时连接失败：分类记录，保留原绑定，允许恢复后重连；不将目标网站错误误判为出口故障。
- IP 持续不可用或被供应商外部移除：显示“原出口不可用/资源已变更”，保留逻辑绑定与原因，不保证已不存在的供应商 IP 能恢复，不静默改用其他 IP。
- 早期约定的“同 session 故障自动换 IP”保留为可选能力，按组明确开启；开启后页面说明该模式允许故障时改变出口。升级不得偷偷把旧的全局开启状态映射为新固定模式下的授权。
- 管理员明确更换、手动轮换、释放绑定仍可用，操作前显示影响。这些是用户主动操作，不属于空闲自动行为。

### 2.3 重启与更新恢复

- 普通重启、Docker 重建、版本更新均恢复当前绑定与原 IP 的对应关系，不仅保留 session 字符串。
- 重启会使已有 TCP 断开，客户端需重连；不能承诺 TCP 流透明续传。
- 恢复时核对供应商列表、节点归属与任务状态，确认原 IP 仍属于账号后恢复该绑定；核对失败时标记待核对，不借机退役或重新分配。
- 自动轮换计划、预算及失效记录同样持久化；重启不清空额度，不集中补执行错过的轮换。

### 2.4 资源容量

- 管理页面区分“已保留绑定”“当前有连接”“空闲但保留 IP”，不再把连接为零理解为未占用资源。
- 长期绑定会占用节点，库存耗尽时拒绝新分配或有界等待，不能自动抢占其他闲置绑定。
- 现有 60% 自动绑定上限改为显式容量设置：最大保留绑定数、最少备用 IP 数。新默认不再隐式扣除 40% 容量，已有显式用户上限迁移保留并说明。
- 最少备用 IP 建议默认 0，允许全部绑定；页面说明留 0 个备用时，换 session 和平滑轮换可能因缺货无法立即完成。
- 保留手动“释放绑定”，明确提示其会结束该 session，并按既有资源退役规则处理，可能消耗更换额度。

## 3. 质量组定时轮换

### 3.1 配置与范围

质量组增加“出口轮换”板块，简单配置优先、高级参数折叠：

| 设置 | 方案规则 |
| --- | --- |
| 定时轮换开关 | 默认关闭；开启后对本组已建立的绑定生效 |
| 轮换间隔 | 用户明确填写，例如 30 分钟；新建组不开启默认计划 |
| 空闲停止时间 | 用户明确填写，例如无连接 10 分钟后暂停；只停止定时轮换，不释放绑定或禁用 session |
| 每日自动轮换上限 | 开启时必填，有限值；0 表示暂停，不表示无限 |
| 本次启用总上限 | 开启时必填；用尽后等待人工调整，不因隔天或重启自动解除 |
| 切换方式 | 平滑或强制，明确说明长连接影响 |
| 故障时自动换 IP | 独立选项，默认关闭；按需授权，不能绕过替换安全预算 |

本版自动轮换仅针对本组已绑定的业务出口，不周期性替换从未分配的备用 IP。组内多个工位分别记录活动时间和到期时间；一个工位连接不能唤醒该组所有闲置工位。

### 3.2 计时、空闲与恢复

1. 首次成功建立业务连接后，开始该绑定的轮换周期。普通重试、协议错误、认证失败不算恢复业务。
2. 存在 TCP 连接时视为使用中，即使暂时无流量也不进入“无连接暂停”。最后连接关闭后才开始空闲计时；配置页面采用“无连接多久暂停”的准确名称。
3. 在空闲宽限期内，计划仍可正常运行；达到所设空闲时长后暂停，保留当前 IP、session 及尚存预算。
4. 再次成功连接时先使用保留的当前 IP，再从此刻重新计一个完整轮换周期，不立即更换，不补执行空闲期间错过的次数。
5. 预算耗尽导致的暂停，不能因为重新连接而自动恢复；需等每日额度重置且总额度仍可用，或人工修改/重新授权。
6. 同一绑定最多一个在途轮换；组内错峰，避免所有绑定同时到期烧掉预算。上一次尚在排空、补货、检测或对账时不重复提交。
7. 用户改 session 后，新绑定重新计时，旧绑定的定时任务取消；组级预算不重置。关闭定时开关后停止新增轮换，已经提交供应商的任务仍要完成对账。
8. 计划改变时预览生效对象、下一次执行时间及额度；不因保存设置立即批量执行。

例：轮换间隔 30 分钟，无连接 10 分钟后暂停。09:00 建连，09:30 完成一次轮换；09:35 最后一条连接断开，09:45 暂停并保留出口；13:00 重连先用同一出口，下一次计划为 13:30。

### 3.3 额度与轮换实现原则

- “更换出口”和“供应商 Replace”分别记账：前者可能先取用现有备用 IP，后者为退役旧节点补货。不能把换出口次数冒充供应商已扣次数。
- 自动轮换既受本组每日/本次启用的有限次数限制，也受账号本地预算、现有组/全局替换预算、供应商真实余额约束。自动轮换开始前预留后续补货所需预算，不能先大量占备用再在补货时发现超限。
- 预算状态分已预留、已提交、已完成、失败、待对账。未提交的取消可释放预留；结果不明的提交保留占用并对账，不盲目重试 POST。
- 跨日、并发工位、重启和多账号均不得让预算重复计数或被重置。每日边界采用工作台明确展示的时区，默认 Asia/Shanghai。
- 实际供应商额度使用新版快照核对；不能只看供应商余额而绕过用户授权的本地上限。数据缺失、过期或未知时暂停新的自动扣费更换并提示同步，已有健康出口继续服务。
- 无合格备用时保留当前绑定、标记等待库存，不先释放旧 IP；不抢占其他工位。
- 平滑切换：新建连接走新 IP，旧连接排空，到期关闭；该时段可能同时存在两个出口。强制切换：关闭旧连接，需要客户端重连。TCP 流无法中途迁移到另一个 IP。
- 本组业务出口仅选质量合格、国家条件兼容的备用 IP；补货后的新 IP 继承原质量组并重新检测，通过后才进入待分配池。
- 质量自动筛查可能产生额外 Replace，必须在授权预算内，不能借定时轮换触发无限筛选、重抽或替换。

## 4. IP 资源池手动更换

### 4.1 交互

- 每行增加有明确背景的“更换 IP”，支持勾选批量；按账号/套餐拆分并串行执行供应商任务，任务页统一追踪。
- 说明两种操作：从现有池切换绑定出口；调用供应商 Replace 更换所选资源。弹窗不能混淆其时机、费用和影响。
- 默认同国家，支持指定国家、随机、供应商可用 ASN、CIDR 网段；高级参数折叠。具体可用范围按对应套餐返回的能力获取，不硬编码无库存选项。
- 所选节点自动决定待更换 IP 列表、账号/套餐和数量；前端筛选可辅助选择，但最终提交锁定明确的资源集合，避免大范围条件误换未勾选节点。
- 显示分组国家/质量约束冲突、供应商剩余额度、本地限制、预计数量与影响的绑定。
- 支持供应商 dry_run 预检；预检与正式提交分开，预检不会修改供应商代理列表。正式提交前重新核对版本、占用状态、预算和资源归属。

### 4.2 正在使用的出口

- 默认仅处理未绑定节点；空闲但长期保留的节点也属于“已绑定”，不能因 TCP 为 0 当作未使用节点。
- 对已绑定出口，必须明确选择等待该绑定达到可处理条件，或现在执行显式换 IP；后者需展示 session 是否保留、是否会断开连接。
- 等待模式不得被无限延后的旧预检授权直接执行；执行前再次确认节点身份与预算，支持取消。
- 管理员明确对长期绑定执行“保留 session 更换 IP”后，客户端配置不变，当前出口更新；这是显式人工例外，不是后台空闲行为。
- 同组符合条件的备用充足时，可先迁移绑定，再处理旧资源；无备用时不得宣称无中断替换。实际供应商替换旧 IP 后，旧连接无法保留。
- 整个任务保留质量组席位，重新检测准入；显示旧/新 IP、供应商任务号、状态、触发来源和错误。重复点击幂等，结果不明则暂停对账。

API 核对依据：[替换对象与参数](https://apidocs.webshare.io/proxy-replacement/proxy_replacement)。国家、ASN、CIDR 和随机是选择条件，不代表供应商保证“高质量/纯家宽”。质量要求由组内检测判定。

## 5. 日志诊断与可观测性

- session 状态：长期保留、已被新 session 替代、人工释放、原出口不可用；不再新增“空闲超时导致失效”。
- 显式释放和替代事件记录原因、操作者/触发源、组/账号/工位、session、原/新 IP、generation、时间、关联任务。
- 连接错误区分网关总连接上限、单绑定连接上限、接入握手容量、绑定容量、无合格资源；记录触发时当前值和上限。协议仍使用标准回复，不扩展私有 SOCKS 错误码。
- 超限先做必要的接纳控制，避免明知无法接纳仍高频建立上游连接。不能通过拒绝连接而失效 session 或触发换 IP。
- 定时轮换可见状态：关闭、运行、空闲暂停、预算暂停、等待库存、排空中、待对账、错误暂停。
- 组页与绑定详情显示当前出口、是否有连接、无连接时长、下次轮换、剩余自动轮换次数、供应商额度和最近结果。
- 对历史失效记录展示“旧版本记录/原因不完整”，不凭时间猜测为已证实的原因；历史错误不改写为成功。

## 6. 设置、运行配置与 AI 接入说明

- 从调度与连接页移除“会话空闲回收”；定时轮换的“无连接多久暂停”位于质量组内，明确不会释放 IP。
- 设置按容量与并发、切换与连接、探测与同步、日志调试分类；每项说明单位、作用对象、何时生效、是否断连、是否可能消耗更换额度。
- 名称改为“单绑定 TCP 连接上限”“最大保留绑定数”，避免混淆浏览器数量、连接数和占用 IP 数。
- 运行配置优先展示服务器公网 IP 140.245.36.206、SOCKS5 入口 140.245.36.206:27538、HTTP 入口 140.245.36.206:22568，以及 HTTPS 管理地址 rapip.aisenno.com；实际值从部署配置读取。
- 监听地址 0.0.0.0 与容器端口放入高级信息，解释监听地址不是客户端可连接地址；兼容环境变量的公网端口映射。
- 故障自动转移、固定/定时模式、长连接超时均读取真实配置，移除写死的“已开启”文字；按组策略时显示“由质量组决定”。
- AI 接入说明更新：完整用户名长期复用；同组同工位改变 session 才主动切换；定时轮换保留配置；不再要求保活或定期生成 session；错误采用分类与有界退避，避免自动无限换 IP。
- 说明匿名 session 的独立绑定行为、手动释放的影响、故障模式的可选性、长连接不能透明迁移。凭据继续使用占位符。

## 7. 数据兼容与发布

- 新字段采用持久化版本与显式迁移；保留账号、节点、质量组、历史检测、供应商快照和预算账本。
- 废弃旧 session_idle_timeout 的回收语义，不把旧值 300 秒自动转成定时轮换暂停时间；不开启自动轮换、不分配默认可消费预算。
- 保留当前仍有效的绑定和原 IP；旧版本已执行完的替换无法逆转，也不能恢复已经失去的原 IP。对旧版已失效配置提供“生成新 session 配置”的引导，不自动复活被明确替代/释放的 session。
- 旧版未提交的空闲回收任务仅在来源可确认时允许取消；来源不明或已提交的任务需对账，不一刀切丢弃。
- 固定绑定与早期全局故障转移配置冲突时显式迁移并显示结果，以本次固定模式语义为准；可选故障转移须重新明确开启。
- 发布前备份数据库、配置、环境变量与旧镜像。长期绑定不再等待“绑定数自然归零”作为升级前提：在无传输连接的窗口操作，持久保留绑定；如有长连接则安排维护窗口，不能强制假装无中断更新。
- 方案批准后进入开发与发布，生产验证不自动开启定时轮换，也不为测试写路径擅自消费更换额度。

## 8. 实施顺序与验收

1. 先改绑定生命周期、重启恢复、容量、故障模式与旧数据迁移，移除自动空闲回收路径。
2. 完善会话/并发错误分类、状态与事件记录，先让行为可解释。
3. 实现质量组定时轮换状态机、有限预算与持久化，再接入页面。
4. 实现资源池手动替换、预检、参数、绑定影响处理与任务对账。
5. 完善设置解释、运行配置、AI 接入说明及规范；模拟验收后再安排生产发布。

必要验收：

- 同 session 断连超过 5 分钟、数小时或重启后，原 IP 仍在且健康时继续使用原 IP，零空闲 Replace。
- session 改变成功只切换一次；并发同 session 不重复分配；旧 session 迟到不回滚；无库存保留原绑定。
- 固定模式节点故障不静默改 IP；选择故障转移后才允许同 session 换出口，并记录证据。
- 定时轮换保持客户端用户名和 session 不变，严格使用本组资源；平滑/强制与长连接行为符合说明。
- 空闲暂停不释放、不更换、不失效；重连从保留 IP 开始计时，不补发错过的轮换。某一工位活动不唤醒其他工位。
- 预算为 0、耗尽、跨日、重启、并发及未知响应均不会无限更换；已用与预留不丢失，暂停原因可见。
- 手动替换能核对所有参数、预算、国家/分组约束；批量按账号归属提交；质量未知或失败的新资源不进入待分配池。
- API 鉴权、CSRF、幂等、预期版本、竞态与失败恢复覆盖真正会消耗额度或改变绑定的路径；低影响文案不新增镜像式测试。
- 测试以模拟供应商和可控时钟为主，不为证明空闲规则真实等待数小时，不擅自消耗生产额度。页面显示值与服务端状态一致。
