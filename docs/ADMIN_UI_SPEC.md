# 首个发布版本管理页面规范

更新日期：2026-11-05。需求已确定：首版需要管理页面，业务以长连接为主，节点故障允许同 session 自动换 IP，用户喜欢 [React Bits](https://reactbits.dev/) 的组件与视觉。已按以下页面范围与技术组合实现，参数可继续调整。

业务规则以 [SPEC.md](../SPEC.md) 为准，架构见 [技术方案](TECHNICAL_DESIGN.md)。首版实现与验证情况见 README.md。

下一版的紧凑总览、历史指标、节点检索、连接记录和质量分组提案见 [v0.2 升级计划](V0.2_UPGRADE_PLAN.md)，分组规则详见 [IP 质量分组方案](IP_QUALITY_GROUPS_PLAN.md)。这些功能已随 v0.2 实现，新增质量分组和连接记录入口；当前交付与验证范围见 [发布说明](RELEASE_V0.2.md)。

## 1. 页面目标

让本人直接判断有没有可用出口、哪些工位仍在连接、换号是否完成、旧连接是否排空、上游补货是否受阻，并完成常用控制操作。

首版是单管理员后台，含登录和退出；不含注册、用户管理、角色配置或计费。建议中文界面、桌面优先，窄屏仍能查询并完成主要操作。

## 2. 技术与视觉建议

- React + TypeScript + Vite + Tailwind CSS。
- React Bits 按需使用 TS + Tailwind 变体；用于局部背景、卡片反馈和轻量过渡，不先导入全部效果。
- shadcn/ui 补充基础表格、表单、下拉菜单、抽屉和弹层，统一设计变量与交互状态。
- 建议深色工作台、克制的渐变/光晕、清晰状态标签，具体配色与布局待视觉评审。
- IP、ID 和数值采用便于扫描的字体与稳定布局，持续轮询不能让表格跳动或丢失选中项。
- 尊重 reduced-motion；动画不作为状态唯一表达。列表、节点状态和任务结果优先保证可读性。
- 官方提供组件源码及独立依赖，实施时逐个核对选用组件版本与成本。参考：[React Bits 安装](https://reactbits.dev/get-started/installation)。

## 3. 六个业务模块

### 3.1 总览

- 当前受管节点、可分配热备、在用、排空、隔离、替换数量，预留未提交单独计数。
- 活跃绑定数、实际 TCP 隧道数、等待请求、当前传输速率与最近刷新时间。
- 各国家热备库存、账号异常、预算不足和补货失败摘要。
- 最近轮换/故障转移事件与正在执行的控制操作。
- 缺货、管理 API 无法访问和进程故障采用不同状态，不显示误导性的统一“离线”。

### 3.2 工位与会话

- 分页筛选 worker、session、国家、账号和状态，匿名 session 有明确标识。
- 展示当前节点、绑定 generation、连接数、最近流量和连接关闭时间。
- 展开查看各 generation 的隧道数、开始时间、字节数、节点及排空剩余时间；不默认记录业务完整 URL 或流量内容。
- “换 IP”默认保留 session，可选平滑/强制；“新 session 换 IP”是独立明确选项。
- “释放”不等待新库存，可以立即停止旧出口使用。
- 连接配置弹窗按需向管理员展示带网关密码的完整链接；普通列表不返回密码、Webshare Key 或上游凭据。AI 接入说明单独复制，不含真实密码。

### 3.3 IP 池

- 按状态、国家、账号分页过滤，展示节点标识、IP、最近验证时间和不可用原因。
- 排空、冷却碰撞、凭据异常、替换失败和等待对账分开说明。
- 展示所有节点的实际归属，不把旧隧道 IP 直接改成当前新 IP。
- 首版不提供绕过冷却、直接将已用节点标成 FRESH 的按钮，不提供默认批量烧号。

### 3.4 账号

- 新增账号时提交写入型 API Key，查看连接验证、套餐选择和完整同步结果。
- 展示账号资源、健康、替换计数、本地预算及其来源；供应商余额未知时显示未知。
- 支持暂停/恢复新分配、修改预算和后续补货国家、触发受控同步。
- 暂停新分配保留已有健康连接和必要替换任务，不能暗中断开全部长连接。
- 密钥从不回显到列表、请求日志或导出数据。首版不做账号删除和跨套餐迁移。

### 3.5 任务与事件

- 展示管理操作、替换任务、故障转移与同步记录，支持筛选、分页和脱敏错误详情。
- 区分“已受理”“等待库存”“新绑定就绪”“旧连接排空中”“供应商补货中”“失败/待核对”。
- 换 IP 成功表示新绑定可供连接，不表示客户端已经完成重连；补货进度独立展示。
- 提交结果不明时显示待核对，不提供会盲目重复 POST 的一键重试。

### 3.6 设置

- 查看有效配置及值来源，编辑允许热改的绑定上限、等待期限、默认切换方式、排空期限和巡检参数。
- 展示长连接无流量超时默认禁用、自动故障转移默认开启；主动测活开关可即时保存，重启保留，开启后立即验证未使用节点。
- 提供冰蓝、紫罗兰、琥珀、玫瑰主题，按浏览器保存；国旗使用本地 SVG 按需加载。
- 监听端口、数据库路径和部署密钥等需要重启的参数明确只读。
- 校验配置后提交，通过同一配置服务应用，失败保留旧生效值并展示原因。

## 4. 长连接交互语义

| 操作 | session 身份 | 旧 TCP | 后续连接 |
| --- | --- | --- | --- |
| 保留 session + 平滑换 IP | 不变 | 在旧出口排空，建议最多 120 秒 | 相同用户名走新出口 |
| 保留 session + 强制换 IP | 不变 | 立即关闭 | 相同用户名重连走新出口 |
| 新 session 换 IP | 更新，旧 session 失效 | 按所选方式排空/关闭 | 客户端使用新用户名 |
| 节点确认故障自动转移 | 不变 | 关闭受影响隧道，流量不重放 | 原 session 重连，缺货则有界等待 |
| 释放绑定 | 当前 session 失效 | 按所选方式排空/关闭 | 业务需创建新 session |

操作区直接显示当前连接数和所选方式的影响；执行后展示 operation_id 的实际进度。页面不使用“无缝续传”或“当前 TCP 已切到新 IP”等误导文字。

平滑切换可在短时间内同时占用两个出口。已有一个旧 generation 排空时，再次平滑切换显示忙碌，用户可以等待或显式强制处理，不自动升级为 hard。

## 5. 刷新与错误反馈

- 首版 REST + 2–5 秒可见页轮询；操作提交后只轮询结果，不重复发控制请求。
- 页面隐藏暂停轮询，断网退避，显示数据更新时间与过期状态。
- 请求失败保留最后一次数据并标识过期，不将未知数量显示为 0。
- 刷新保持筛选、分页和选中对象；对象 generation 变化后阻止基于旧版本重复控制。
- 请求包含幂等键和预期 generation；连接中断后查询原 operation_id，不能生成新键再发一次。
- 不要求首版 WebSocket 或 SSE，后续有更高刷新需求再评估。

## 6. 登录与发布

- 管理员登录与 SOCKS5 密码分离，脚本 Bearer Token 不放浏览器持久存储。
- 服务端会话 Cookie 使用 HttpOnly/SameSite，HTTPS 使用 Secure；写请求验证 CSRF/Origin，登录失败受限流保护。
- 页面、静态资源与 API 同源发布，API 使用 `/api/v1`，前端路由回退不吞掉 API 404。
- Docker 构建阶段生成静态资源，生产 Python 容器直接提供页面，不运行 Vite 开发服务器或额外 Node 服务。
- 默认通过本机/受保护网络访问；页面退出撤销管理员会话，不影响业务代理隧道。

## 7. 首版验收

1. 登录后展示真实账号和节点，错误/缺货/未知状态准确，凭据不回显。
2. 一条长时间静默隧道持续存在时，不被绑定空闲回收或页面刷新关闭。
3. 保留 session 的平滑/强制轮换均可操作，旧 generation 与新节点展示准确。
4. 模拟节点故障，session 不变，客户端重连获得新出口；页面显示故障转移而非原 TCP 恢复。
5. 无热备时操作失败或等待有明确结果，不抢占、不误报换号成功。
6. 断网、重复点击、刷新和过期页面不会重复烧号或控制错误 generation。
7. 账号新增、配置应用、操作追踪与退出形成完整闭环；生产镜像中页面可直接访问。
