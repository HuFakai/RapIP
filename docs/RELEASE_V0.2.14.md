# v0.2.14：IP 轨迹定位与补货失败恢复

## IP 轨迹

搜索 IP 或从资源池进入 IP 轨迹后，服务器在保留的相关链路中找到这个 IP 最近一次直接出现的事件（包括原 IP、新 IP），自动返回该事件所在分页。页面滚动到对应事件，目标 IP 用金色高亮，相关链路仍完整保留。可使用“定位目标 IP 最近事件”再次定位。

首次定位后，正常翻页和实时刷新不会持续强制滚动。没有直接事件时保持相关历史，不伪造事件或补齐已过保留期的记录。

## 补货失败

过去池内切换成功后，旧 IP 的补货可能在供应商预检阶段失败，任务已终止但资源仍保留 `REPLACING`。该状态不会自动继续执行，因此界面会误导用户以为任务还在运行。

现在持久化前和启动恢复时核对资源与任务状态：

- 失败且确认未提交（实际尝试为 0、无供应商任务 ID）的原绑定，保留原 IP／session。
- 已切换到其他出口的旧资源解除陈旧绑定引用，标记“补货失败”，保留原因并暂停分配；不把已使用的旧 IP 当作新出口。
- 清理未提交任务的额度预留，不退款或重放结果不明的实际提交。
- 存在 `UNCERTAIN`、在途任务或原位恢复任务的资源继续保持对账保护，不自动重试或回收。
- 可使用现有“更换 IP”预检与提交流程人工重试，遵守额度与质量规则。预检错误区分超时、供应商状态和响应校验失败；仅明确缺货才允许随机兜底。

本版不通过升级自动提交真实更换。旧数据无需手工改库，保留原 Docker Compose 数据和配置即可升级。发布前照常备份，等待无活动 TCP／等待请求／换号任务后重建网关。

回退必须成套恢复发布前数据库、配置和旧镜像，不只更换旧代码；本版资源快照新增补货失败说明字段。
