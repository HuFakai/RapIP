# v0.2.13：追踪可读性、账号与数据管理

## 工作台

- 代理追踪及从 IP／工位跳入的轨迹默认“看最新”，保留“从头看”和实时更新。宽屏左侧讲解事件、右侧显示国家、IP、工位与 session；窄屏自动折行。检查通过、暂停分配、换号等采用状态颜色和标签。
- 删除质量分组时保存名称，历史显示“分组名称（已删除）”。升级时从尚存的分组创建／更新操作恢复旧名称；若此前名称已经丢失，仅显示分组 ID 加删除标记，不编造名称。今后的追踪事件也保存当时的分组名称。
- 上游账号改为响应式卡片，宽屏可同时显示三列；备注、节点、可分配数量、供应商换号与套餐用量、编辑／删除／暂停操作集中在卡片中。支持名称、备注和 ID 搜索。

## 登录与代理凭据

“网关设置 → 账号与安全”分别修改管理登录和 SOCKS5／HTTP 代理入口。两类修改都必须验证当前管理密码，新密码为 12–128 字符；代理密码 UTF-8 长度不能超过 SOCKS5 的 255 字节限制。

管理登录修改后撤销所有浏览器登录会话，管理 API Token 不变。代理凭据修改后，新连接使用新凭据；已有 TCP 继续，工位、session、IP 绑定不变。重新复制完整链接更新客户端，沿用原 worker/session 时继续原出口。

配置独立保存在 `config/credentials.json`，原子写入、权限 0600；管理密码使用带随机盐的 scrypt 哈希，代理密码用于拼接链接，保存在私有配置文件中。凭据不进入调度快照、追踪或通用前端重试缓存。该文件不进入 Git 或镜像。

环境变量仍用于首次初始化；页面修改后以持久化文件为准。更新部署输出会读取实际代理凭据，已经修改的管理密码不会回显，也不会把旧环境变量密码当作当前密码展示。备份时一并保护 `.env`、`config/` 和 `data/`。

## 数据存储与生命周期

目前仍使用 SQLite，两个数据库职责不同：

| 数据 | 位置 | 清理策略 |
| --- | --- | --- |
| 调度、绑定、供应商替换与额度账本 | `gateway.sqlite3` 的状态快照 | 保留恢复与预算所需状态 |
| 代理追踪 | `gateway.sqlite3` 的独立 `lifecycle` 表 | 默认 30 天、最多 20,000 条，可分别配置 |
| 管理操作、运行事件 | 状态快照中的 operations/events | 已结束操作默认 30 天；运行事件 30 天且最多 1,000 条，进行中和幂等保护结果保留 |
| 连接、测活、质量报告 | `observability.sqlite3` 的 `records` 表 | 成功连接 24 小时；异常、测活和报告 7 天；共最多 100,000 条 |
| 分组／账号／全局趋势 | `observability.sqlite3` 的 `samples` 表 | 默认 30 天；7 天后压缩为 15 分钟 |

追踪与连接记录、任务事件不是同一份记录。释放或删掉连接日志不会同时删掉对应的追踪，追踪受独立期限和条数控制。历史清理可能使长链路的早期事件不再可见，不会重新推断缺失历史。

### 本次优化

- 默认趋势存储精度由 10 秒改为 60 秒，可选择 10／30／60 秒。仍每 5 秒更新计数和刷新当前时间桶；新数据的行增长约为原来的六分之一，流量与请求计数不抽样。不同精度合并时累加计数，不使用忽略冲突导致丢失计数。
- 没有业务路由／目标的认证失败或协议错误按“进程、分钟、协议、结果”合并；连接页显示合并次数。真实工位/session 请求仍单独记录，统计中的尝试与失败总数保留全部次数。合并不回写旧明细。
- 页面容量显示两个数据库及各自 WAL，不计共享内存文件，并分别列出观测库、调度与追踪库、追踪条数和运行事件。
- 每小时按策略清理，支持立即清理。清理后执行非阻塞 WAL checkpoint；释放页供后续写入复用，不在业务期间强制 VACUUM。清理不保证文件立刻缩小。
- 观测有效数据超过阈值时暂停明细，计数仍继续；清理到阈值以下后恢复原来的日志模式，用户选择的模式不被改成“关闭”。

### 当前是否需要换数据库

2026-11-08 只读检查：7 个 IP，494 条追踪，约 9.9 万条采样、2.19 万条连接／测活明细，其中约 1.49 万条是认证失败。观测主文件约 50.5 MB，调度主文件约 1.56 MB，另有 WAL。主要增长来自固定频率、多维度采样和公网未认证请求，不是代理追踪。

参考 [SQLite 官方适用场景](https://sqlite.org/whentouse.html)，结合本项目的单进程、本地磁盘部署，此规模先优化采集与保留即可，无需因为这些行数迁移数据库。SQLite 保持单网关进程、本地磁盘和 WAL；未来若有多实例调度、多个写入服务或持续写入锁竞争，再规划 PostgreSQL 等独立数据库。现有保护阈值仅保护可丢弃的观测明细，不承诺整个服务器磁盘永远不会增长，仍应监控磁盘、备份和重要账本规模。

## 升级与验证

保留原配置、数据库和凭据，使用现有 Docker Compose 部署流程。在无活动 TCP、等待请求或换号任务时备份再重建容器；不可只复制运行中的 SQLite 主文件漏掉 WAL。

凭据修改和重新登录用本地隔离环境验收，不修改生产凭据。验证包含 HTTP／SOCKS5 新旧认证、绑定保持、浏览器登录撤销、重启恢复、统计合并总数与并发写入、旧分组名、追踪保留与容量，以及宽屏／手机布局。线上只读确认页面与数据恢复，不消耗供应商换号额度。
