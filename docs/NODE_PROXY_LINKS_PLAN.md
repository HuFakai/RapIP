# IP 资源池协议链接复制：待确认方案

状态：2026-11-06 讨论稿，尚未实现。本次上线范围仅为页面加载反馈和弹窗滚动修复。

## 对需求的理解

每行增加 SOCKS5、HTTP 两个复制按钮，直接复制包含用户名、密码、服务器地址和端口的 RapIP 完整代理 URL。不是直接导出 Webshare 上游凭据。

- 已绑定，包括没有 TCP 连接但长期保留的 IP：使用服务端当前真实绑定的 group、worker/匿名标识、session、country 构建链接；不重新生成 session、不轮换、不新建另一绑定。
- 待分配且已准入的 IP：生成指向本行资源的待使用配置。复制不分配、不预占、不改变 FRESH，不启动检测、轮换或 Replace，也不消耗更换额度或绑定容量。
- “未使用不限制”暂理解为不限复制次数、不会因为复制后空闲而过期；只要资源仍有效且可分配，就可首次使用。普通 TCP 并发限制、质量准入和独占分配仍生效。

建议同一未使用 IP 复用一份持久化的待使用 worker/session，SOCKS5 与 HTTP 共用同一身份。多次复制同一配置不会生成无数 session，也不会轮流把同一工位切换、使旧链接失效。

## 首次使用与独占

现有用户名只按分组分配，并不能保证取得列表中某一行 IP。不能只在前端拼一个普通随机 session 链接就声称它指向选中资源。

后端需要保存“待使用身份 -> 资源周期/节点 ID”的映射，复制阶段不占用该节点。真实客户端请求经过鉴权后，原子校验目标资源、分组、质量和可用状态，再建立绑定，指向该行 IP；失败鉴权和单纯读取链接不算使用。上游连接失败时遵循长期绑定与错误分类，不擅自换 IP。

同一配置的并发首连合并到一个绑定；不同身份争抢同一个 IP 时只能有一个成功。待使用资源如果被其他业务先分配，旧待使用身份不能抢占、不能触发另一工位换 session，也不能静默改取其他 IP，应提示资源已占用并引导重新复制当前有效配置。

绑定后重复使用已复制的同一配置继续有效，之后点击行内按钮同样返回当前绑定链接。用户主动更换同工位 session 后沿用现有轮换规则，旧 session 不复活。管理员明确保留 session 换 IP、或已开启本组定时/故障轮换时，链接可不变而出口按明确授权变化。

## 可用状态与失效边界

- FRESH 且真实可分配：生成/复制待使用配置。
- IN_USE 且能解析到当前有效绑定：复制当前配置，包括空闲保留。
- DRAINING：旧代次不能建立新连接，不生成指向旧 IP 的新链接。
- 隔离、未通过质量准入、替换、归档或找不到有效绑定：按钮禁用并解释原因。
- 原资源被供应商替换、归档、移组或发生不兼容身份变化：旧待使用链接不能绕过这些变化，提示重新复制。

待使用配置和有效绑定均持久化，普通重启不让链接过期。读取/复制配置接口需要管理鉴权；复制由明确点击触发，密码按 URL 编码，不进入日志。

## 实施顺序

1. 用户确认“未使用不限制”及同一未使用 IP 复用同一配置的语义。
2. 增加持久化待使用映射、首连指定节点的原子占用与冲突处理。
3. 增加行内 SOCKS5/HTTP 一键复制，自动读取服务器公网主机与端口。
4. 验证复制零分配、两个协议共享身份、重启后可用、并发首连、其他工位先占用、资源替换/移组、已绑定真实链接及所有受限状态。

本方案不把“点击复制”或“获取配置”变成一次真实代理连接。
