# RapIP v0.2.12：用事件解释实际使用过程

代理追踪改为逐事件的时间线。每个事件说明发生的操作和结果，显示 IP、国家旗帜与代码、工位、session；Webshare 换回的新 IP 单独显示。点击 IP 查看相关绑定和补货过程，点击工位查看该项目的历次链接。聚焦一个对象时默认从头看，也可以切到最新在上。旧版未记录的新 session 请求不会补造，旧事件缺少的上下文显示“未记录”。

释放会话绑定现在只让旧 session 失效并归还原 IP，不创建新的 Webshare 任务。平滑释放先排空现有 TCP，强制释放立即关闭 TCP；回到池前仍需符合分组准入。重启后继续这一归还语义。以前已提交的补货任务不会被释放操作撤销。轮换出口与客户端更换 session 仍按分组策略取得新 IP、退役旧 IP 并补货，可能消耗额度，弹窗现已说明。

质量网络证据增加备用出口回显源，记录每次尝试的服务、错误阶段及耗时。无法取得回显和真实出口不一致分别说明；证据不足不会触发质量自动替换。备用源成功时，延迟以该成功请求为准，不把主源等待失败的时间算作 IP 延迟。

Ping0 自查询默认关闭，可在设置单独启用。通过被检测 IP 自身、以浏览器 TLS 配置访问固定首页；只接受明确匹配该 IP 的报告。单次最长 35 秒，响应有大小上限，全局单查询、至少间隔 30 秒，缓存 10 分钟。遇验证页或限流后冷却，不自动解验证或切换出口重试。HTTP 200 的验证页同样标为未取得报告。站点验证仅作为该站可访问性的参考；不自动作为家宽认证、不合格判定或 Webshare 替换依据。报告按测活日志保留策略清理。

部署仍使用 Docker Compose。升级前备份，等待业务连接和替换任务空档，再重启网关。此前项目配置、预算、绑定和英国 IP 均应保留。proxy-lab 为用户本地文件，本次不修改、不打包到容器。
