# IP 质量分组与自动准入方案

日期：2026-11-05。状态：v0.2 已实现。自动更换仍由组级开关和预算控制，默认关闭；当前资源保持默认组，不自动替管理员划分项目。外部检测源需配置自己的 Key，真实供应商联调范围见 [发布说明](RELEASE_V0.2.md)。

## 1. 需求与边界

由管理员主动选择受管 IP，创建多个资源分组；每组单独设置质量要求。只有满足该组要求的 IP 才进入该组待分配池。明确不合格时可自动调用现有供应商 Replace 流程，新 IP 继承原组并重新筛查，直至通过或触达预算/停止条件。

例如为账号注册业务设置高要求组，为数据采集项目设置基础组。分组是同一管理员下的项目资源隔离，不等同于多用户授权；不承诺某个网站的注册成功率或业务接受度。

关键原则：质量准入是已有连通性、去重、冷却、独占和预算约束之外的附加条件，不能绕过原有约束。

## 2. 分组与资源归属

- 创建组时填写名称、稳定 group_id、用途说明，勾选要纳入的 IP；不默认把全部账号或全部新同步 IP 纳入。
- 一个组可以从多个已配置账号选 IP，同一账号也可分别提供资源给多个组。
- 首版每个资源只属于一个组，组间不共享待分配 IP；重复物理 IP 仍按全局规则隔离。组标签不能绕过跨账号去重或冷却。
- 未选择的 IP 留在 `default` 默认组，继续原有基础健康准入，不参加其他组的质量筛查，也不因其他组的质量规则被换掉。
- 空组库存为零，不自动购买 IP，不自动从默认组或其他组挪用资源。
- 分组纳入的是稳定“资源席位”，不是永久绑定一个 IP 字符串。席位关联账号/套餐和当前节点；同一席位换出新 IP 后仍归原组。
- 默认维持选定席位数量，不因质量失败无限增加资源。组内“目标热备量”不能突破该组拥有的席位数量；使用中、排空中、检测中和替换中均占席位。
- 首版只允许迁移未绑定、未使用且无在途替换的资源。活跃、排空、已用待退役、UNCERTAIN 资源不能直接挪组；先按生命周期处理，必要时等待新使用周期。
- 删除组前必须没有活跃绑定、排空、检测或替换任务；剩余未用资源退回默认组并重新走默认准入。归组变更须审计。

建议先把现有 6 个 IP 中的少量资源选入一个试验组，观察只读检测的真实通过率，再扩大覆盖。文档示例用“高要求组 3 个席位 + 基础组 3 个席位”，仅演示隔离，不实际修改资源。

## 3. 质量检测体系

### 3.1 指标与获取方式

| 类型 | 指标 | 获取方式与用途 |
| --- | --- | --- |
| 基础连通 | 代理认证、SOCKS/CONNECT、HTTPS 探测成功率、实际出口 IP | 从服务器经待检上游访问固定探测目标；不通过业务 acquire 创建绑定 |
| 性能/稳定性 | 端到端建立及响应耗时、连续成功次数、超时率 | 固定目标、受控样本与时间窗口；不同目标/流程的耗时不混为纯 RTT |
| 归属与地区 | 国家、ASN、运营商、已识别网络类型 | 第三方属性源，记录来源与更新时间；供应商标签不等同独立验证 |
| 网络属性 | hosting、Tor、VPN、proxy 等已识别信号 | 独立字段，可设允许/拒绝/仅提示；不合成无法解释的“纯净度” |
| 信誉记录 | 滥用举报置信分、报告数量、最近报告时间 | 信誉源查询；保存原始口径，不能称为注册失败概率 |
| 系统内部约束 | 已使用、冷却、跨账号重复、账号异常、资源代次 | 原调度器始终强制执行，不能由质量评分覆盖 |

检查实际出口与供应商节点是否一致；无法可靠确定出口时暂缓准入，不悄悄用服务器自身 IP 的检测结果代替代理出口。

### 3.2 数据源建议

首版采用可替换的检测源适配器，建议先实现两个外部适配器和内置网络检测：

- **内置网络检测**：不依赖新的信誉服务 Key，可检查真实出口、连通性和耗时；会产生少量代理流量。不得声称因此已经完成信誉或住宅属性验证。
- **IPinfo 适配器**：用于地区、ASN 与按套餐可获得的网络属性；不同产品返回字段不同，按实际 API 权限显示能力，不能假定免费基础接口包含所有属性。[官方 API 概览](https://ipinfo.io/developers/ipinfo-api)、[属性字段说明](https://ipinfo.io/developers/ip-privacy-detection-api-data)。
- **AbuseIPDB 适配器**：只使用查询能力获取举报相关信誉信号，不调用 report 接口上传举报。`abuseConfidenceScore` 基于该服务的举报评价，不是通用“质量分”，也不是欺诈/注册风险概率。[官方 API 文档](https://docs.abuseipdb.com/)。

默认不购买服务、不自动创建第三方账号。设置页提供服务能力、Key 配置、连通校验、限额、缓存命中和最近错误。管理员配置有效 Key 后，才可把对应能力设为分组必需项。高要求组缺少必需检测源时保持未就绪；基础组可明确不要求该维度，但不能显示“信誉已通过”。

外部信誉/属性查询由服务器直接访问检测服务，仅发送待查询 IP 等必要字段；不把 Webshare Key、上游代理账号密码、业务内容或 session 发给检测服务。检测源 Key 只在服务端私有配置保存。

### 3.3 判定方式

- 使用“硬性条件 + 提示项”，首版不引入跨供应商混算的万能 0–100 分。
- 硬性条件支持布尔值、数值阈值、国家/ASN 允许或拒绝列表、样本数与成功比例；组内所有必需条件同时成立才通过。
- 网络类型的来源未给出“住宅”分类时，不把 `hosting=false` 自动等同于真实住宅；未知值不能补成 false。
- 当前购买的就是代理服务，`proxy`/`vpn` 等标签默认作为提示，由管理员显式选择是否设为拒绝项，避免预设规则拒绝整个代理池。
- 检测状态区分 PASS、FAIL、UNKNOWN、ERROR、EXPIRED。来源、样本量、规则版本和证据有效期随结果保存。
- 阈值不符合且数据完整，才得到 FAIL；API 超时、401/403、429、缺字段、覆盖不足、结果冲突属于 UNKNOWN/ERROR，不触发质量自动换号。
- 信誉分为 0 或查不到举报均不保证“从未使用”或“网站一定接受”；页面展示具体证据及其局限。

### 3.4 两个策略模板

下表是首次调参的示例，不是行业合格线，也不自动应用到当前 6 个 IP。先只读预览通过率，再启用自动换号。

| 条件 | 高要求业务组（示例 ID：register） | 基础数据采集组（示例 ID：collect） |
| --- | --- | --- |
| 连通样本 | 初始连续 3 次成功 | 初始 3 次至少 2 次成功 |
| 成功样本最大探测耗时 | 1,500ms | 5,000ms |
| 国家 | 按项目指定，例如 US | 按项目指定或任意国家 |
| 网络属性 | 可要求已验证 ISP 类归属，拒绝 hosting/Tor | 可允许 hosting；Tor 默认拒绝 |
| AbuseIPDB 分 | 可选启用，示例 ≤10 | 可选不要求，或示例 ≤50 |
| proxy 标签 | 默认提示，不单独拒绝 | 默认提示，不单独拒绝 |
| 属性/信誉证据有效期 | 建议 6 小时 | 建议 24 小时 |

“3 次样本”只说明初始化窗口的结果，不称作长期稳定性。性能门槛与服务器地区、探测目标及样本流程有关，必须根据首轮实测调整。国家要求若同时来自组策略和客户端 country，取交集；交集为空时明确拒绝。

## 4. 准入、自动更换与停止条件

```text
手动选择 IP → 纳入资源组 → 等待检测（禁止新分配）
                         ↓
                 基础健康 + 组质量规则
                 ├─ PASS → 该组待分配池 → 该组业务绑定
                 ├─ FAIL → 自动换号已开启且预算允许 → 持久化替换任务
                 │                                      ↓
                 │                         新 IP 继承原组/原席位 → 重新检测
                 └─ UNKNOWN/ERROR/超限 → 隔离等待、退避或暂停，不盲目换 IP
```

- 不合格资源不能进入默认池或其他低要求组“兜底”。默认按所属组规则处理；需要挪组时由管理员显式操作，不能绕过使用历史和冷却。
- 关闭“自动更换”只做检测和隔离；开启后，确认不合格且预算允许的任务自动处理，不要求每个 IP 重复点确认。
- 加组/改策略时先展示只读预览：预计通过/不合格/未知数、命中条款、可用检测源与最多允许替换数。自动更换为组级独立开关，初始关闭，防止创建草稿即大量换号。
- 单次延迟抖动先按采样规则复核；整批节点同时网络失败、检测目标故障或检测源异常时暂停该轮质量换号，不能把相关故障当作所有 IP 都差。
- 替换统一经过现有账号串行队列、持久化与幂等流程；质量模块不能绕过调度器直接 POST Replace。
- 每次提交前原子校验并预留组/席位轮次预算、账号总预算及全局预算，供应商提交计数按现有保守口径持久化。并发任务不能共同越过余额上限。
- 单组配置每轮替换上限、每日上限、每席位连续替换上限、换号间隔；检测服务调用次数另外限额，和 Webshare 替换额度分开统计。
- 建议首轮默认：每席位最多 3 次连续质量替换、每组每日最多 5 次；具体启用值在组预览中确认。所有上限取交集，任何一项耗尽即停止，不承诺一定筛出足量 IP。
- 连续次数按稳定席位/筛选轮次记录，不因换成新 IP、新建 job、切换进程或修改组名而归零；预算账本不允许通过移组/重命名规避。
- 预算同时覆盖质量失败换号、补货后再次质量失败和冷却碰撞重抽；一次替换不能同时记成质量换号与业务补货两次提交。组间公平排队，严格组不能持续阻塞其他组的补货。
- 组每日预算以明确配置的时区结算（默认 Asia/Shanghai），内部时间记录 UTC，页面显示实际重置时间；迁移/重启不重置当日计数。
- 达到上限时显示 BUDGET_BLOCKED/RETRY_LIMIT/PAUSED 与原因，不自动降低质量要求、不借其他组 IP、不持续无限换号。
- 供应商结果不明仍标 UNCERTAIN，暂停同账号后续替换并等待人工核对；不能靠再次提交猜测结果。

## 5. 与现有状态、会话和长连接的关系

资源状态与质量状态分开记录，避免把质量待定和供应商故障混成一种结果。新纳入且未用资源处于 QUARANTINED，组内 PASS 后才可成为 FRESH；调度分配还必须同时满足：

`属于请求组 ∧ 账号正常 ∧ 未用 ∧ 非冷却/非重复 ∧ 基础健康准入 ∧ 当前组规则版本通过 ∧ 必需证据未过期`

- 组质量开关与现有“主动测活”开关分开。手动质量检查可显式执行网络探测，页面展示效果；关闭主动测活不能暗中把强制基础健康验证跳过。组质量条件启用时，所需检测不能完成就暂停准入。
- 修改策略会递增 policy_version；未分配库存重新判定，不再使用旧规则的 PASS 继续新分配。原始证据仍新鲜时可复用，只重算规则。
- 质量过期的未分配节点暂停准入并后台复检；检测服务异常不得默认改成合格。
- 默认质量周期检查仅针对未绑定资源，不突然关闭活跃长连接。已有绑定保留分配时的策略版本与证据快照，页面标记“旧策略绑定/待后续复检”；新策略不追溯改变当前绑定。
- 如管理员明确选择强制退役活跃资源，沿用已有 graceful/hard 和预期 generation，提前展示连接影响及预计补货额度。
- 同 session 自动故障转移和显式换 IP 只能选择原组内已合格热备；组内缺货按现有有界等待后失败，不借其他组资源或静默降级要求。
- 业务释放、轮换或空闲回收后的正常补货，新节点仍留原组并经该组完整准入；未纳入质量组的 default 组保持原有健康准入。

## 6. 客户端按项目选组

v0.2 新增用户名字段：

```text
admin-group-register-worker-01-session-a1b2c3
admin-group-collect-worker-01-session-a1b2c3
admin-country-US-group-register-worker-01-session-a1b2c3
```

- group_id 为 1–32 位 ASCII 字母数字，展示名称可以中文；完整用户名仍不超过 255 字节，字段顺序固定，不允许混用分隔符。
- 明确组的匿名 session 也可支持；未传 group 的旧客户端继续使用 default 组，不进入质量专属组。
- 绑定及失效 session 的命名空间扩展为主体 + 组 + worker（或匿名 session），不同组的同名工位互不替换。旧绑定迁移为 default 组。
- 同一绑定的组身份固定；迁移项目必须释放/新建绑定，不能把修改 group 参数伪装成现有 TCP 原地迁移。
- 管理 API 的 rotate/release/按 worker 定位需带 group 或使用 binding_id，不能跨组误操作同名 worker。
- 连接配置弹窗增加分组选择、该组合格库存/未就绪原因，生成对应完整链接和 AI 接入说明；示例名称与真实已建组保持一致。
- 分组路由只做当前单管理员的资源隔离；未来多用户另增加凭据到组的服务端授权，不能把用户名里的 group 当作权限证明。

## 7. 页面设计

新增“质量分组”模块，避免把复杂策略全部塞进 IP 池的一行工具栏：

1. 组列表：名称/用途、拥有席位、合格热备、在用、待检、不合格、未知、替换中、今日质量换号/上限和自动更换开关。
2. 创建向导：选 IP（账号/国家筛选）→ 设规则/检测源 → 只读预览 → 配置额度 → 保存并按需开启自动更换。
3. 组详情：成员表、逐项检测证据和不合格原因、策略版本、检测与替换历史；可只读复测、暂停和调整规则。
4. 总览增加组筛选与质量摘要，账号/组筛选贯穿指标、图表和列表；监控新增通过率、未知数、检测费用/调用量、质量换号数和预算阻塞。
5. IP 池增加组、质量结论、更新时间/过期时间、命中规则；将“能连但质量不满足”与“网络不可用”分开显示。
6. 任务页区分业务轮换、健康故障、质量拒绝和冷却碰撞；一笔供应商提交只记一次实际替换消耗。

每个拒绝结论可解释，例如“国家不符”“探测耗时超过上限”“信誉值超出阈值”；未知单独说明“检测源配额不足”，不只给红色分数。

## 8. 数据模型、实现顺序与验收

关键业务数据包括 group、policy_version、resource_slot、成员归属、质量证据引用/有效期、准入结论及预算预留；这些必须随关键状态持久化，不能只保存在可丢弃的观测库。观测库只保存详细历史和聚合曲线；缺少准入证据时重新隔离，不能猜测为 PASS。

检测结果携带节点代次、实际 IP、成员版本、规则版本、源版本和时间戳。提交结果时再次核对，避免异步旧结果把已经换号/移组/改规则的节点重新放入池。替换完成先对账关联原席位，无法唯一关联时保持隔离，不把未知新 IP 随意分到其他组。

缓存按 IP + 检测源 + 查询参数复用证据，规则判定按组/版本独立。组 A 的失败不是组 B 的失败，组 A 的通过也不能直接当作组 B 的通过。检测并发、源速率、单轮任务量和缓存容量有界，业务转发线程不等待第三方评分 API。

实施顺序建议：

1. 先实现默认组迁移、成员/席位模型、分组调度和连接配置，确保隔离。
2. 接入内置检测及外部检测适配器，完成只读预览和可解释的组准入。
3. 加入持久化预算、质量替换队列、继承原组、连续失败停止与异常熔断。
4. 接入紧凑看板、组级时序和连接记录；在模拟环境覆盖边界，再单独说明真实联调额度。

验收至少覆盖：

- 只筛选选中的成员；其他组/default 资源没有被质量任务扫描或替换。
- 同一组可跨账号；同账号可有多个组；同一资源不能同时加入两组。
- 严格组不合格、基础组可能合格的证据能按不同规则正确解释，禁止自动跨组挪用。
- 不合格 IP 不被分配；新 IP 回原席位/原组重检；缺货不降低质量门槛。
- 检测源未知/超时/无权限/限流/冲突不触发 Replace；相关网络故障不批量烧号。
- 并发、重启、移组与改名均不能突破预算；最多替换次数可精确验证；UNCERTAIN 不自动重发。
- 过期/旧策略/旧代次/已取消检测结果不能重新准入；活跃长连接默认不受组配置变更影响。
- 原用户名兼容 default；不同组同名 worker/session 隔离，rotate/release 不误操作。
- 关键状态备份/恢复包含组归属、准入与预算；观测故障时不开放未合格节点。
- 所有列表、日志、AI 说明和导出均不泄露检测 Key 或上游密码；检测不创建真实业务绑定。

## 9. 默认方案

采用“一个资源一个组、选中成员才检测、证据逐项判定、组内独立待分配池、失败自动替换有上限、检测未知不换号”的设计。检测源建议为内置网络检测 + 按需启用 IPinfo/AbuseIPDB；不在尚无 API Key 时伪造信誉检测通过。

首轮通过只读预览确定现有套餐是否能满足某组门槛；如果通过率很低，应调整资源来源或规则，而非期待无限替换必然找到合格 IP。具体第三方套餐、字段权限、可用额度和策略阈值在接入时验证，当前不承诺费用或通过率。
