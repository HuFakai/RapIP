# v0.2.2：出口质量参考与运行显示

- 资源池、工位、连接及任务显示质量组名称和 ID；连接用户名使用稳定 ID。
- 资源池每行新增“质量”操作，打开 IPQuality 参考报告。支持按需检测、后台执行、再次打开读取、证据缺失提示；不创建业务绑定、不切换 IP、不调用 Replace。
- IPQuality 使用固定版本的数据库模块，显示分来源原始评分、网络类型、风险标签，报告先核验实际出口。第三方查询可能拒绝或缺失，不能据此保证业务成功；未纳入分组准入/自动换号。模块范围、独立运行限制、许可与来源见 [免费检测说明](FREE_IP_QUALITY.md)。
- 卡片、图表坐标轴与悬浮提示统一适配流量单位，并限制小数位。统计接口保持字节计数。
- 设置新增全局与单工位并发连接上限，保留现有配置值；调整只限制新连接，不主动断开已有连接。压测触及工位 128 条时，可按资源情况自行调到 256。
- SOCKS5 不支持的命令独立归类，记录命令号/返回码；上游失败记录保留已解析的目标、资源组、账号和出口，便于定位。不会把不支持的 UDP 命令当成节点失效触发换 IP。

## 当前质量等级

| 预设 | 网络样本 | 成功样本最大耗时 | 证据有效期 | 额外证据 |
| --- | --- | --- | --- | --- |
| 基础可用 | 3 次至少成功 2 次 | 5000 ms | 24 小时 | 无第三方 Key 要求 |
| 稳定优先 | 3 次全部成功 | 2500 ms | 12 小时 | 无第三方 Key 要求 |
| 高质量 | 3 次全部成功 | 1500 ms | 6 小时 | 必须有 IPinfo、网络类型 ISP、排除 hosting/tor，AbuseIPDB 举报置信分 ≤ 10 |

各预设只是参数起点，管理员可展开自定义。PASS 只证明已要求且已取得的证据满足本组策略；缺少必需证据保持 UNKNOWN，不准入、不按质量失败更换。当前单 IP IPQuality 报告不是官方 API Key 的替代品，不会悄悄改变现有组策略。

## 升级与运行

仍使用 Docker Compose 构建。新镜像包含 Bash、curl、jq、bc，以及随 Python 包分发的固定检测模块。无需在宿主机安装脚本依赖。检测进程在 Docker 内不继承管理 Token/供应商凭证环境。

升级需要重建网关，已有长连接会断开；业务绑定可能按原恢复规则退役并更换节点。请在没有测试连接和活动绑定时部署。可以先构建新镜像，再使用该镜像的一次性容器执行只读检测验证，保持现有网关运行。

依赖锁文件已改用 npm 官方源重新解析，直接依赖版本未变化；修复不可获取的 tinyglobby 旧锁定版本及少量构建依赖补丁锁定，随后重新安装和构建验证。
