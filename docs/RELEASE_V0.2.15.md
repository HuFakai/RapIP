# v0.2.15：绑定 IP 质量复检与新手引导

## “质量待复检”是什么意思

旧界面的“已过期”是质量证据超出分组有效期（默认 24 小时），或分组策略／检测源配置更新后需要重新评估。它不是供应商 IP 套餐到期，也不是 session 失效。

旧实现仅自动检查未使用资源，绑定 IP 被跳过，因而长时间固定使用的 IP 会一直显示过期。同 worker、session 的正常绑定仍可继续建立连接，已有 TCP 不受质量结果过期影响；重新分配只使用该组有效 PASS 资源，释放后若证据过期，会先隔离再复检。

## 本次改进

- 界面改为“质量待复检”，展示原绑定保留、自动／手动复检提示及过期原因。资源池的质量筛选采用中文选项。
- 开启“主动测活”时，启用质量组中正常绑定／预留的 IP 在结果临近到期或失效时自动复检。每轮最多安排 3 个，使用现有检测并发上限；成功后保留至少 5 分钟的调度间隔，避免第三方缓存即将过期时重复检测。未确认通过时 15 分钟后再试。
- 主动测活关闭时不安排绑定 IP 的自动复检，仍可点击资源池“复检”。该按钮只适用于正常绑定的命名质量组；默认资源组沿用基础健康检测。
- 复检只更新检测结果、检测时间和延迟。即使 FAIL 或 UNKNOWN，也不释放绑定、不关闭既有 TCP、不改变 worker/session/代次、不提交 Webshare 替换。不会将使用中的 IP 放回公共待分配池。
- 检测期间若 IP、绑定、代次、session、分组策略或检测源版本变化，丢弃旧结果。已有原位换号任务、补货受阻或正在检测的节点不参加本次绑定复检。
- 代理追踪增加“绑定 IP 质量复检”事件。AI 接入说明同步解释 EXPIRED 与保留绑定的关系。

手动接口：`POST /api/v1/nodes/{node_id}/quality-refresh`，遵循现有管理鉴权、Cookie CSRF 和 Idempotency-Key 规则，返回可查询的管理操作；不消耗 Webshare 更换额度。诊断仍会使用少量代理流量，第三方源沿用已配置的访问权限及请求预算。

## 新手引导

侧栏新增“新手引导”，代理总览提供可关闭的入口。六节内容：

1. 添加上游账号，区分供应商 API Key、管理登录与代理凭据。
2. 查看默认资源、质量组和检测结果有效期。
3. 复制普通待用／指定 IP 链接，使用 HTTP 或 SOCKS5 接入，完成第一次真实代理连接。
4. 理解 worker、session、长期固定与三种动态切换方式。
5. 使用 IP 轨迹、连接记录与任务排查过期、证据不足、补货失败、库存不足和旧 session 等问题。
6. 配置凭据、额度与日志保留，区分释放、复检、切换和供应商替换的成本。

页面读取真实账号、IP、绑定与保留的成功连接记录。生成链接、取得绑定不自动算作连接成功。“已读”仅记录当前浏览器阅读进度，与实际接入完成状态分开；不保存密码、Key 或完整代理链接。

引导可直接打开添加账号弹窗、普通链接弹窗、AI 配置说明与对应管理页面。不会自动创建账号／分组、预留 IP、开启自动替换或修改额度。

浏览器兼容说明参考 [Chromium 官方代理文档](https://github.com/chromium/chromium/blob/main/net/docs/proxy.md#socksv5-proxy-scheme)，标准 Chrome 的 SOCKS5 不提供代理认证，浏览器自动化可使用现有 HTTP 入口。

## 验证与升级

延续 Docker Compose 部署，保留 `.env`、`config/`、`data/`。无活动连接／等待请求／供应商任务时备份并重建；无需手工迁移数据库。线上验收不更换 IP 或修改现有凭据与预算，核对绑定和供应商提交计数保持一致。

验证覆盖：绑定复检的 PASS／FAIL／UNKNOWN、规则变更时丢弃结果、并发防重、自动测活开关、近过期源缓存节流、真实接入状态与空部署状态、六步引导跳转、手动复检和手机布局。
