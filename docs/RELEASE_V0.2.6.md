# v0.2.6：指定 IP 预留、普通待用链接与双质量报告

> 自 [v0.2.7](RELEASE_V0.2.7.md) 起，Ping0 改为快捷跳转，以下自动查询说明仅适用于 v0.2.6。

## 代理链接

IP 行内新增 SOCKS5 / HTTP，复制完整网关代理链接。待分配 IP 首次复制立即预留并绑定工位；已绑定节点复制当前真实身份。预留不建立业务连接，其他工位不能占用。

资源池右上角“复制代理链接”按组生成普通待用配置，不预留 IP。未使用时复用，使用后生成下一工位；工位用尽明确提示复制行内已绑定链接。规则与边界见 [链接与工位说明](NODE_PROXY_LINKS_PLAN.md)。

取消未使用预留不消耗更换额度；已被使用则拒绝取消。原 v0.2.5 固定 IP、保持 session 轮换、有限额度定时轮换规则继续有效。

## 两种独立报告

- IPQuality：原有固定版本开源模块、综合参考分与证据明细继续保留。
- Ping0：服务器只读 GET `https://ping0.cc/ip/<IP>`，获取位置、ASN、ASN 所有者、企业、IP 类型、风控值、原生 IP、共享人数。网页未提供字段显示未知；超时、限流、页面变化不会伪造通过结论。
- Ping0 风控值越高风险越大，与 IPQuality 综合分方向不同，分别展示。家宽标签不代表真实家庭线路认证；不混合成无来源分数。
- 大模型检测需在 Ping0 网页点击，本版提供来源链接，不自动调用内部接口。
- 网关设置 → 质量检测源提供两个独立开关，默认开启；关闭阻止新任务，历史仍可读，已开始任务继续完成。
- Ping0 单次查询最少间隔 10 秒、不重试、不跟随跳转、正文最多 2 MB。只查询公共 IP，固定 HTTPS 源，第三方 HTML/脚本不注入管理页面。
- 两份报告均不改变分组 PASS / FAIL，不触发 Replace，遵循“测活与质量报告”保留期限与记录上限。

## 升级与兼容

持久化 schema 4，保存预留、普通待用身份、工位规则和检测开关。现有组默认兼容自定义工位，原绑定及配置保留；新组默认使用受管编号。备份 / 回滚必须包含数据库、账号与配置、旧镜像，不能仅换旧镜像读取新状态。

生产部署更新会重建容器并中断 TCP；选择连接空档发布，客户端重新连接后沿用原 session / IP。发布与验收记录另见 [部署文档](DEPLOYMENT.md)。

实测限制：2026-11-06 本机能够直接取得 Ping0 数据，但当前部署服务器收到 Cloudflare / Aliyun 人机验证页面（HTTP 200）。程序明确识别为 PING0_VERIFICATION_REQUIRED 并保留原报告；当前服务器的自动抓取受第三方限制，不宣称已经可用。可通过报告中的来源链接手动查看。

- 187 项后端测试、9 项前端测试、Ruff、TypeScript 与 Vite 生产构建通过。
- 模拟环境验证两个协议共用指定预留出口、取消与首次连接竞争、session 更换、普通身份使用后再生成、池耗尽、鉴权 / CSRF、重启及保留期限。

- Ping0 线上查询明确返回需要人机验证，不产生质量数据、资源更换或额度扣减。此次验收没有提交真实 Replace。
