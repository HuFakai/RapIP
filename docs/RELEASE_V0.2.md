# RapIP v0.2.0

日期：2026-11-05。本版实现紧凑运行看板、分组质量准入、受控自动替换、历史指标与连接记录。原有 SOCKS5/HTTP CONNECT、session 粘性、独占、冷却及两种切换语义保留。

## 使用入口

- 总览：8 项紧凑指标、账号/组/时间范围筛选；吞吐与运行趋势两张主图；节点池、连接建立、探测任务、耗时分布和累计流量通过趋势选择切换。图表按需加载。
- IP 资源池：IP/CIDR、账号、分组、国家、状态、质量结论过滤，服务端排序与 20/50/100 条分页；列设置保存到浏览器，节点详情展示准入证据。单节点探测不提交 Replace。
- 质量分组：选择未用资源创建组、规则模板/自定义阈值、只读预览、成员调整、准入检查、暂停/恢复和新轮次。每次成员操作最多 100 个；可多次添加，组总量不因此限制为 100。
- 连接记录：默认仅保存失败元数据；可关闭或开启全量。按时间、协议、账号、组、worker/session、目标主机和出口 IP 查询；活跃连接单独查看。关闭明细不关闭聚合指标。
- 设置：四套主题、紧凑/舒适密度、主动测活、日志采集、分组每日全局替换预算和质量检测源。
- 连接弹窗：选择分组、公网/SSH 模式，复制完整 URL、结构化 HTTP 配置、curl 示例和不含真实密码的 AI 接入说明。

## 质量组的操作顺序

1. 先在“网关设置 → 质量检测源”按需配置 IPinfo / AbuseIPDB。Key 不回显；未配置时可用内置网络检测，不能视为已验证信誉或 ISP 属性。
2. “质量分组 → 创建质量组”，从默认组选择未使用资源，设置 ID 和用途。
3. 设置网络样本、成功数、耗时、有效期，以及需要的国家/ASN/属性/信誉条件；执行只读预览。
4. 检查不合格与未知原因后设置预算。默认自动更换关闭，只检测并隔离；启用后确认 FAIL 且预算允许的资源会进入现有供应商替换队列。
5. 客户端选择该组生成配置。示例 `admin-group-register-worker-01-session-first`；组 ID 只含 1–32 位字母数字。旧格式继续使用 default，不借用其他组库存。

归属按稳定资源席位持久化，换出的新 IP 返回原组。组内缺货有界失败，不静默跨组降级。新策略作用于后续准入，活跃绑定保留原策略版本和已有连接；强制换号仍需显式操作。

网络检查经待检上游发起 HTTPS 出口查询；信誉/属性 API 由服务器直接查询指定 IP，不发送代理凭据。外部结果缺失、超时、无权限或限流标 UNKNOWN，不自动消耗 Webshare 替换额度。当前只读实际网络目标是 `api.ipify.org`；基础健康探测继续使用原有 generate_204 流程，耗时分布分别按目标查询。

## 预算与恢复

- 自动更换默认关闭。默认建议组每日 5 次、本轮 10 次、每席位连续 3 次，60 秒间隔；全局非默认组每日预算为 20，可设置为 0 暂停分组提交。默认组仍受原账号预算约束。
- 组预算覆盖本组所有实际替换提交（业务、质量、健康或碰撞），每笔供应商提交只计一次；账号总预算和各组/全局上限同时校验。
- 每日口径采用 Asia/Shanghai（UTC+8）。重启、IP 更换和组改名不重置计数；新筛选轮次只重置轮次 ID，不能清除每日与席位连续限制。
- 已提交结果不明仍为 UNCERTAIN，暂停同账号后续提交。预算阻塞任务保留，调整配置或额度刷新后受控恢复；不要在供应商后台核对前盲目重试。
- 关键状态在 `data/gateway.sqlite3`，源 Key 在 `config/quality_sources.json`。该文件已排除 Git 与 Docker 构建上下文。

## 观测口径与存储

独立 `data/observability.sqlite3` 保存尽力采集的监控数据，不保存关键准入事实；观测库故障不阻塞代理转发。服务端每 5 秒采样，10 秒桶保留 24 小时、分钟桶保留 7 天、15 分钟桶保留 30 天。数据从本版启动后积累，不回填升级前没有采集的历史。

默认仅失败连接明细保留 7 天，全量成功明细保留 24 小时；记录上限 100,000，写入队列上限 2,000，过载丢弃明细并显示计数。观测库达到 256MiB 时暂停明细采集。物理文件删除记录后空间可被后续写入复用，不承诺每次清理立即缩小文件。

连接成功率是代理建立结果，包含认证、库存拒绝与上游失败分类；不是业务注册或目标 HTTP 成功率。SOCKS5/CONNECT 内部 HTTP 状态不可观测。日志不记录完整 URL 参数、Cookie、认证头或载荷。断档和进程边界不绘成连续有效流量。

## 部署与回退

沿用 `bash scripts/deploy.sh`；升级前备份 `.env`、config 和完整 data。建议避开业务高峰，重建容器会关闭长连接，已用节点恢复可能触发补货。

v0.2 将旧资源、会话和任务归入 default，并写入 schema 2；不自动选择真实 IP 创建业务组。原密码、账号及预算计数保留。原版程序不能直接读取新增字段，回退必须停止网关，恢复升级前一致备份并使用旧镜像，不能仅切换源码。

正式管理域名可用 `RAPIP_PUBLIC_ADMIN_URL=https://your-domain/` 设置部署信息展示；代理仍通过 PUBLIC_PROXY_HOST 指定可达 IP。HTTPS 反代和证书配置独立于镜像更新，已有配置继续保留。

## 验证范围

发布前 Python 测试 97 项、前端辅助测试 6 项、TypeScript 严格检查和生产构建通过。新增测试覆盖组隔离、原组换号、未知不替换、并发预算、旧结果拒绝、恢复、只读预览、日志脱敏、历史持久化/聚合、观测故障和 10,000 节点分页。数据规模测试不等于生产吞吐承诺。

模拟浏览器验证已完成选 IP、只读质量预览、创建分组和基础准入。实际服务器发布验收另记录在 VALIDATION.md；外部检测源未提供真实 Key，因此不宣称已验证真实信誉套餐权限。真实自动质量换号的网络提交路径以模拟供应商验证，当前服务器默认关闭，不消耗额外实测额度。
