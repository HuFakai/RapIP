# RapIP v0.2.10：IP 动态切换与双泳道追踪

在「质量分组 → IP 动态切换」为每个组选择策略。已有分组升级后默认维持「仅从池内切换」；保存设置不会立刻换 IP。

| 策略 | 已使用工位以新 session 连接 |
| --- | --- |
| 仅从池内切换 | 获配同组合格备用 IP，退役旧 IP 并异步补货。等待库存超时，原绑定保留。 |
| 池内优先 · 缺库存时原位替换 | 有合格库存时沿用上述流程；没有符合条件的备用 IP 时，申请替换当前 IP。 |
| 始终原位替换 | 不使用待分配池，直接申请替换当前 IP。 |

原位替换复用 Webshare 分组补货规则、账号余额和本地预算、分组预算与冷却。连接带有明确的国家条件时不跨国兜底；如果与分组指定国家冲突，或无法与 ASN/网段条件同时提交，原位切换在扣额度前拒绝。指定目标的预检明确无库存时，按分组配置决定是否随机兜底；单个原位任务最多真实提交一次。首次连接、同 session 重连、手动切换、定时轮换和故障转移不使用这项新策略。

网关对每个工位持久化一个原位任务。从排队到 Webshare 对账、质量准入期间，新 session 只更新该任务的候选。同一个旧候选的重试不能覆盖更新的候选。网关在真实提交时关闭旧 TCP；新连接等待本次任务，默认 25 秒。若客户端先超时，任务仍继续，客户端应退避并重试同一个新 session。合格后由最新候选使用新出口；原位提交不会迁移已建立的连接。成功后默认冷却 60 秒；已经真实提交但被供应商明确拒绝的任务也进入冷却。

提交结果不明时暂停自动替换，保留原任务供核对；新 IP 不合格则隔离并保持工位锁定，不会继续扣额度。已拿到 IP 但准入受阻时，可以从资源池重新探测，或在工位释放该未准入绑定。默认资源组若关闭主动测活，可手动探测以完成准入。

代理追踪按链路起点倒序展示，三秒自动刷新。每条链有业务与补货两个泳道，记录不足时耗时显示为「—」。长链可水平滑动，也可展开成 Z 字逐节点查看。工位列表可以复制当前绑定的 SOCKS5（含导入别名）或 HTTP 链接，复制不会申请新 IP。

生产部署仍使用 Docker Compose。镜像升级会重启网关，已有 TCP 需要重建。升级后不会自动把任何质量组切成原位模式；启用前应先确认备用库存和预算。若已启用原位模式，回滚前先确认没有在途或待核对的原位任务。
