# v0.2 升级计划：紧凑总览、运行观测与质量分组

日期：2026-11-05。状态：方案待讨论；本文中的看板、历史指标、连接日志和 IP 质量分组尚未实现。

本次已经授权上线的部署调整与下一版本开发分开验收：管理入口使用 HTTPS 域名，代理使用服务器公网 IP；总览重构待方案确认后实施。参考用户提供的 Resin 总览、请求日志、节点池截图，采用它的监控与检索思路，保留 RapIP 现有深色和四套主题。

## 1. 当前问题和目标

- 总览有大块入口介绍、装饰连线和 IP 卡片，桌面首屏可读数据少。现有资源区实际只查 6 条节点，未来不应简单扩大卡片数量。
- 传输曲线是浏览器保存的最近 30 次采样，刷新后丢失；不能标成“最近 6 小时”历史。
- 服务端目前有状态、字节累计、账号计数、任务、最近检查时间；没有延迟分布、历史吞吐、连接尝试成功率或连接日志表。
- 监听地址、管理域名和客户端实际代理地址是三个概念。页面经过 Cloudflare 时不能把页面域名直接当成 SOCKS5 地址；SSH 隧道下的 localhost 也不代表服务器公网地址。

目标：打开总览即可判断库存够不够、账号是否正常、连接是否异常、补货是否受阻；账号/IP 增多时，总览高度和查询量保持有界。

新增业务目标：管理员仅选择需要筛查的 IP 建立多个质量组，每组设置不同准入要求；不合格资源在限定预算内自动换号，新 IP 继承原组并重检，项目只获得本组合格资源。完整设计见 [IP 质量分组与自动准入方案](IP_QUALITY_GROUPS_PLAN.md)。

## 2. 发布范围与优先级

| 阶段 | 内容 | 交付标准 |
| --- | --- | --- |
| 部署修正，立即处理 | HTTPS 管理域名、公网代理发布、显式 PUBLIC_PROXY_HOST、安全 Cookie、证书续期 | 域名可登录；连接弹窗默认服务器 IP；公网两个代理端口握手可达且要求认证 |
| P0：紧凑总览 | 缩小页头、8 个指标、异常优先、账号/国家库存摘要、快捷连接入口 | 1440×900 可见主要指标、趋势区和列表摘要；IP 增多不增长出无限卡片 |
| P1：分组质量准入 | 选择 IP 建组、组级规则、独立待分配池、检测源、只读预览及有预算的自动替换 | 只有该组合格资源可分配；换出新 IP 继承原组；未知不换号、缺货不跨组降级 |
| P1：真实观测数据 | 服务端时序采样、历史吞吐/连接数/池状态、探测耗时与分布、连接建立统计 | 刷新页面仍能查历史；图表明确单位、时间窗口、缺测与统计口径 |
| P1：节点表格增强 | 多条件过滤、排序、列设置、分页、单节点只读探测 | 国家/账号/状态/出口 IP/最近检查/失败原因可快速定位 |
| P2：连接记录 | 可控采集开关、失败分类、条件查询、详情抽屉、保留期限 | 默认仅记录错误；开启全量后可追踪连接，记录开销不阻塞代理 |

建议 P0、P1 和基础 P2 一起作为 v0.2 发布，按阶段实现并预览。质量分组涉及调度和预算，先定义默认组迁移、资源席位和分组隔离，再接自动质量换号与组级指标。高级自定义看板、告警通知、Prometheus、多用户统计和大规模容量扩展放到后续版本。

## 3. 总览布局

方向：紧凑的运维控制台。保留冰蓝/紫罗兰/琥珀/玫瑰；主要依靠数字、状态、表格和轻量图表表达信息。React Bits 仅保留局部交互，不在密集表格上渲染多层光效。

### 3.1 布局草案

```text
页头：代理总览 | 账号/分组筛选 | 时间范围 | 自动刷新 | 更新时间 | 连接配置
指标：库存 / 已验证资源 / 活跃会话 / TCP / 吞吐 / 建立成功率 / 补货 / 账号
趋势：上传下载吞吐（较宽）              | TCP 连接与节点池状态（切换）
摘要：账号与国家库存（最多 8 行）         | 异常待处理 / 最近事件（最多 6 行）
```

- 页头高度目标约 48–56px，区块间距 12–16px；指标卡约 72–80px，表格行约 36–40px。
- ≥1600px 指标可排 8 列；1280–1599px 排 4 列、2 行；窄屏渐进收为 2 列/1 列，保留操作可达。
- 1440×900 的验收重点是首屏同时呈现指标、主趋势、库存和异常摘要，不要求首屏容纳全部明细。
- 删除总览的大幅 GATEWAY 装饰区；“连接配置”提升到页头，展示 IP/端口的精简入口条可复制。
- 出口资源默认用紧凑表格/摘要。卡片视图作为可选项，最多预览 8 条，不随资源总数无限展开。
- 总览不堆完整节点列表；“全部节点/异常节点/缺货国家”进入带现有筛选条件的 IP 池。
- 总览摘要明确“展示 8 / 共 N 项”，不能把截断列表伪装成全部结果。

### 3.2 八个指标

| 指标 | 主值与辅助信息 | 点击去向 |
| --- | --- | --- |
| 可分配库存 | 可分配 FRESH；总节点/在用/隔离/排空 | IP 池，带状态筛选 |
| 健康验证 | 最近有效验证健康数、验证覆盖率；未知单独展示 | IP 池，按验证状态筛选 |
| 活跃会话 | 活跃 worker 与匿名 session；容量上限/等待分配 | 工位与会话 |
| TCP 连接 | 当前隧道数；选定窗口峰值/新建数 | 当前连接及记录 |
| 实时吞吐 | 下载与上传 B/s；窗口累计字节 | 吞吐趋势 |
| 连接建立成功率 | 成功数 / 完成建立结果的尝试数；失败分布 | 失败连接记录 |
| 补货与预算 | 执行中/失败/UNCERTAIN/预算阻塞；本地替换计数 | 任务页 |
| 上游账号 | 启用数/总数；异常、同步失败与暂停数 | 上游账号 |

口径约束：

- “可分配”沿用调度器实际 eligibility，不能直接用节点 state 代替。
- 健康验证使用明确的有效期（初始建议 30 分钟）、最近探测/业务成功证据及覆盖率；过期、未测、禁测均不能当作失败或健康。最终有效期与测活周期联动校验。
- 成功率按客户端连接尝试统计，一次故障转移重试不能被重复计为多个客户端请求。认证失败、协议错误、库存/限额拒绝、上游失败分别计数；业务目标 HTTP 200 不是这个指标的含义。
- 一条代理隧道有客户端和上游两个 socket，不将二者相加冒充两个业务连接。可另列“上游拨号中/已连接”，但要说明定义。
- 本地替换预算和网关计数不是 Webshare 实时剩余额度；250GB 套餐配置也不能直接用于绘制“供应商已用流量”。
- 健康验证和质量准入是不同结论；按组展示合格热备、待检、不合格、未知、检测源异常、质量换号次数与剩余本地预算。组内缺货不能用其他组的合格数掩盖。

| 参考模块 | RapIP 实现建议 | 优先级 |
| --- | --- | --- |

## 4. 节点池、连接记录与入口体验

### 4.1 IP 池

- 搜索 IP、节点 ID；国家、账号、状态、验证结果组合筛选，支持明确的 IPv4/IPv6 CIDR 查询。
- 后端排序和分页，20/50/100 行；固定表头、列显隐，刷新保留筛选/排序/页码。
- 列：IP + 国旗、账号、资源状态、绑定工位、当前连接数、探测耗时、最近检查、连续失败、原因、操作。
- 单节点“探测”明确是只读检查，只更新验证信息，不直接调用 Replace、不把已用资源重新准入；运行中节点不因手动测试被强制断开。批量探测必须限速和排队。
- 行详情抽屉说明状态变化、归属、最近错误、相关补货任务，减少跳页。

### 4.2 连接记录

- 默认保存失败元数据；设置可切换“关闭/仅失败/全量”。指标聚合独立于明细日志开关。
- 按时间、协议、账号、worker/session、出口 IP、目标 host、网络结果过滤；目标默认只记录 host:port。
- 字段包含开始/结束、建立耗时、连接存活时长、字节数、关闭原因、失败分类、绑定 generation、关联任务 ID；活跃长连接从打开记录查询，关闭后补全结束字段。
- 不记录代理密码、Authorization、Cookie、完整 URL query、请求体或流量载荷。
- SOCKS5/HTTPS CONNECT 内部的目标 HTTP 状态、页面首字节、业务注册成功与否无法直接观测，显示“不适用/不可观测”，不解密 TLS 来凑字段。
- 首版不扩展明文 HTTP 响应解析；仅统计已确认的连接建立结果，避免将截断响应或 CONNECT 200 误标为业务成功。
- 初始保留策略：失败记录 7 天，全量记录 24 小时；最多 100,000 条，达到预算按最早记录清理；监控库达到磁盘保护阈值时停止明细采集并报警。
- 异步有界写入队列、批量落库；过载时丢弃观测明细并计数，不能拖慢业务代理。成功率等聚合计数在原事件点计算，不从有损日志反推。

### 4.3 连接配置

- 明确显示“管理地址”“客户端代理地址”“实际监听地址”，不再用管理页 hostname 猜测公网代理入口。
- 服务器以 `RAPIP_PUBLIC_PROXY_HOST` 作为直连地址；公网端口通过现有 PUBLIC_*_PORT 显式覆盖。当前部署使用服务器 IP，避免 Cloudflare 管理域名被误用为原始代理。
- 默认选择已部署的“公网直连”，可切换“SSH 隧道”，隧道使用 localhost 和对应本地转发端口。
- 默认地址由后端配置下发；未知时明确要求填写，不能把服务端 0.0.0.0 或容器内网 IP 生成为客户端链接。
- 保留完整 URL 与结构化 server/username/password 两种复制方式，增加 curl / 浏览器自动化示例；AI 说明保留密码占位符。
- 连接生成只组装配置，不创建绑定、不消耗更换额度。
- 增加质量分组选择及本组准入状态，生成规划中的 group 用户名字段；未传组的旧客户端使用 default，不能无意进入高要求项目专属池。新格式在分组调度实现前不可使用。

### 4.4 质量分组

新增独立“质量分组”模块：选择成员、设置硬性条件与提示项、检查检测源能力、预览通过率、设置预算后启用自动替换。每个资源只归一组；替换结果继承稳定席位和原组。既有连通性探测是只读操作，质量拒绝后的自动 Replace 是单独受控的写操作，界面明确区分。详见 [质量分组方案](IP_QUALITY_GROUPS_PLAN.md)。

## 5. 数据与技术方案

继续使用现有 FastAPI + asyncio + SQLite + React/TypeScript/Vite；不为监控功能改写代理核心或增加多个调度进程。

- 新建独立 `observability.sqlite3`，与关键调度状态快照隔离。使用 WAL 和批量写入；监控损坏/锁等待不能阻塞换号状态持久化。
- 业务接入点增加计时与计数：连接尝试 → 认证/分配 → 上游建立 → attach → 流量 → detach；只读探测单独记录结果和耗时。
- “探测耗时”指固定探测流程的端到端耗时，包含网络及目标响应，不宣称为纯 RTT。探测目标/重试次数一并记录。
- 每 5 秒服务端采样当前连接和池状态；字节与建立结果按事件增量累计，跨进程启动标记边界。浏览器刷新不影响采样。
- 初始桶策略：10 秒聚合保留 24 小时，1 分钟聚合保留 7 天，15 分钟聚合保留 30 天。通过原始增量累计成桶，禁止把速率直接求和当作流量。
- 默认历史维度做全局、账号与资源组，协议用于建立统计；不为每个 IP/目标/session 都按 5 秒生成时序行，不预生成账号×组×国家的全量组合。按节点的耗时分布来自有界探测记录。
- API 返回实际分辨率、覆盖范围、样本数量和缺测标记；进程停止、缺测、计数器重置不补成零流量。
- 新增 `GET /overview` 聚合快照、`GET /metrics` 时序、`GET /connections` 查询、`GET /probes` 查询和受控的单节点探测接口；同账号筛选须贯穿指标、图表和摘要，避免一页混用不同范围。
- 概览快照和历史查询各自轮询，复用已请求数据，避免每个指标卡单独发请求；实时 5 秒刷新，页面隐藏暂停前端刷新，后台采样继续。
- 图表建议 Apache ECharts：用模块化导入，只加载折线、柱状、tooltip、缩放等需要的能力；表格先复用现有组件并补后端分页。仅在长列表实测需要时加入虚拟化。
- 当前 `App.tsx` 较集中，实施时拆分 Overview、Nodes、Connections、图表及筛选组件，避免继续把新功能塞进单文件。
- 不新增 Redis、ClickHouse、TimescaleDB 或复杂监控服务。超出单机能力后根据实际压测结果制定独立升级方案。
- 组归属、规则版本、准入证据引用与预算预留属于关键调度状态，必须持久化；观测库仅保存明细历史，不能因日志丢失而把未知资源当成合格。检测适配器和有界队列复用现有异步架构，第三方评分不进入业务建连热路径。

## 6. 实施与验收

建议顺序：数据口径/分组模型 → 分组调度与只读质量预览 → 有预算的质量替换 → 后端采集与查询 → 紧凑总览/节点池 → 连接记录 → 服务器小流量验收。可先用模拟 API 并行预览紧凑 UI。用模拟数据覆盖 1/10/100 个账号、100/1,000/10,000 个节点；这些是验收数据量，不是生产吞吐承诺。

验收重点：

1. 1440×900 桌面首屏可扫描主要指标、趋势、库存和异常；更多账号/IP 不扩大总览预览条数；窄屏操作不被裁切。
2. 所有数字来自后端，不用随机曲线填图；无历史/缺测/未知有明确展示。刷新后仍能查看之前时间段。
3. 筛选联动、分页、排序和钻取可回退，不丢上下文；1 万条节点通过后端分页访问，禁止一次下载全部后前端过滤。
4. SOCKS5、CONNECT、库存拒绝、鉴权失败、上游失败、重试和正常关闭的指标口径有自动测试，避免双计数。
5. 观测库满、队列过载或查询慢时，代理继续转发，关键调度状态仍可持久化；UI 报告观测降级。
6. 开关关闭后不继续生成明细；导出/API/图表 tooltip 均无凭据或敏感 HTTP 内容。时间以用户浏览器时区显示，桶边界与查询使用 UTC。
7. 升级保留 `.env`、config 和 data；初始化监控库不会清空原状态。降级可忽略新监控库，不能悄悄改变 session/换号语义。
8. 服务端回归优先只读测试。任何新建并释放真实会话、真实 Replace 均预先说明额度，本轮不新增上次授权之外的替换测试。
9. 质量分组只检查选中成员；新 IP 回原组重检；严格组/基础组规则独立，组内缺货不借用别组资源。检测源异常不换号，并发和重启不会突破预算或重发 UNCERTAIN。

## 7. 需要讨论的默认建议

- 保留深色与四套主题，默认紧凑；舒适密度作为可选项。参考 Resin 的信息组织，不复制其浅色外观。
- 历史范围默认 1 小时、保留上限 30 天；首屏仅放吞吐和连接/池状态两张主图，其余通过页签展开，避免为了更多数据堆满九张大图。
- 日志默认仅失败，全量采集由设置开启。优先完成定位问题所需字段，业务 HTTP 状态不强行伪造。
- 继续采用单管理员与单调度所有者。多用户、账单和平台租约概念不混入本次版本。
- 质量采用“硬性条件 + 提示项”，不先造统一纯净度分；检测源初步规划为内置网络检查、可配置 IPinfo 属性与 AbuseIPDB 信誉查询。先只读预览，按组设置额度后再开启自动更换，不默认把全部 IP 纳入。
